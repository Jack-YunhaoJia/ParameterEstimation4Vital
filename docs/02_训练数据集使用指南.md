# preset-first 数据集结构解析与使用方法

> 本文档面向模型训练、数据分析和调试协作者，说明当前 `preset_corpus_dataset.h5` 的真实结构、字段含义、解析方法和使用建议。

## 1. 数据集概览

当前 `preset-first` 数据集由 `PresetDatasetProducer` 生成，最终文件名为：

- `preset_corpus_dataset.h5`

配套产物通常还包括：

- `corpus_schema.json`
- `production_summary.json`
- `checkpoint.json`
- `shards/`

其中：

- `preset_corpus_dataset.h5` 是训练和分析的主入口
- `corpus_schema.json` 是 schema 的独立 JSON 表达
- `production_summary.json` 是本轮生产摘要
- `checkpoint.json` 和 `shards/` 主要用于 resume

## 2. HDF5 完整结构

当前 HDF5 结构如下：

```text
preset_corpus_dataset.h5
├── train/
│   ├── param_values
│   ├── present_mask
│   ├── embeddings
│   ├── base_preset_id
│   ├── variant_id
│   ├── route_mask_json
│   ├── sample_id
│   ├── midi_note
│   ├── midi_velocity
│   ├── midi_duration
│   ├── rms_db
│   └── split_local_index
├── val/
│   └── (同 train)
├── test/
│   └── (同 train)
└── metadata/
    ├── param_names
    ├── param_types
    ├── param_value_encoding
    ├── default_values
    ├── corpus_min
    ├── corpus_max
    ├── presence_ratio
    ├── category_values_json
    ├── route_edge_schema_json
    ├── corpus_schema_json
    ├── run_mode
    └── checkpoint_manifest_json
```

## 3. split 级别字段说明

### 3.1 `param_values`

- 形状：`(N, D)`
- 类型：`float32`
- 含义：统一的监督矩阵，所有可训练字段都被编码到这里

编码规则：

- `continuous`：直接写数值
- `binary`：直接写 `0.0 / 1.0`
- `categorical`：先映射为 `category_id`，再写成 `float32`

这意味着：

- `param_values[:, j]` 的真实语义必须结合 `metadata/param_names[j]`
- 如果该字段是 categorical，还必须结合 `metadata/param_value_encoding[j]` 和 `metadata/category_values_json`

### 3.2 `present_mask`

- 形状：`(N, D)`
- 类型：`uint8`
- 含义：标记字段是否真实存在于原始 `preset.settings`

解释：

- `1`：该字段在原始 preset 中存在
- `0`：该字段在原始 preset 中不存在，`param_values` 里是默认值填充

训练时如果你想区分“真值”和“补位值”，一定要把 `present_mask` 一起读出来。

### 3.3 `embeddings`

- 形状：`(N, 1024)`
- 类型：`float32`
- 含义：MuQ 音频 embedding

注意：

- 当前 producer 如果无法初始化 `EmbeddingExtractor`，会退回零向量占位
- 正式训练前建议先抽样检查 embedding 是否退化为全零

### 3.4 `base_preset_id`

- 形状：`(N,)`
- 类型：字符串
- 含义：样本对应的基础 preset ID

一个 `base_preset_id` 可能对应：

- 原始 variant
- 多个 route-masked variants
- 每个 variant 下多个 MIDI 条件样本

### 3.5 `variant_id`

- 形状：`(N,)`
- 类型：`int32`
- 含义：该样本属于 base preset 的第几个变体

约定：

- `0` 一定是未掩码的原始 preset
- `1..k` 是 route mask 变体

### 3.6 `route_mask_json`

- 形状：`(N,)`
- 类型：字符串
- 含义：当前样本对应的路由掩码

JSON 结构示例：

```json
{
  "mask_vector": [1, 0, 1],
  "masked_edge_names": ["signal:osc_1->filter_1"]
}
```

### 3.7 `sample_id`

- 形状：`(N,)`
- 类型：字符串
- 含义：样本唯一 ID

当前实现使用 `uuid4()` 生成，因此：

- 它是全局唯一标识
- 不应依赖其字面顺序表达任何结构信息

### 3.8 `midi_note`

- 形状：`(N,)`
- 类型：`int32`
- 含义：当前渲染条件的 MIDI 音高

当前默认值来自固定 6 条件：

- `48`
- `60`
- `72`

### 3.9 `midi_velocity`

- 形状：`(N,)`
- 类型：`int32`
- 含义：当前渲染条件的 MIDI 力度

当前默认值：

- `80`
- `120`

### 3.10 `midi_duration`

- 形状：`(N,)`
- 类型：`float32`
- 含义：当前样本的渲染时长

当前 `preset-first` 实现里，这个字段默认是：

- `2.0`

因为当前 `RendererBackend` 还没有为 `preset-first` 主线接上自适应时长。

### 3.11 `rms_db`

- 形状：`(N,)`
- 类型：`float32`
- 含义：预处理前原始音频的 RMS（dB）

常见用途：

- 数据质量筛查
- 静音样本分析
- 条件间 loudness 差异观察

### 3.12 `split_local_index`

- 形状：`(N,)`
- 类型：`int32`
- 含义：当前 split 内部的行号

注意：

- 它只在 split 内局部唯一
- 不能当作全局样本 ID
- 主要用于 resume / finalize 后的完整性审计

## 4. metadata 级别字段说明

### 4.1 `param_names`

- 形状：`(D,)`
- 类型：字符串
- 含义：`param_values` 每一列的字段名

### 4.2 `param_types`

- 形状：`(D,)`
- 类型：字符串
- 取值：`continuous` / `binary` / `categorical`

### 4.3 `param_value_encoding`

- 形状：`(D,)`
- 类型：字符串
- 取值：`identity` / `category_id`

解释：

- `identity`：`param_values[:, j]` 可以直接按数值解释
- `category_id`：`param_values[:, j]` 是类别编号，必须再查 `category_values_json`

### 4.4 `default_values`

- 形状：`(D,)`
- 类型：`float32`
- 含义：当字段缺失时写入 `param_values` 的默认填充值

### 4.5 `corpus_min` / `corpus_max`

- 形状：`(D,)`
- 类型：`float32`
- 含义：字段在语料中的最小值和最大值

注意：

- 它们处在“编码后的 float 域”
- 对 categorical 字段来说，这代表的是 `category_id` 的最小值和最大值

### 4.6 `presence_ratio`

- 形状：`(D,)`
- 类型：`float32`
- 含义：字段在整个本轮语料中出现的比例

### 4.7 `category_values_json`

- 类型：标量字符串
- 含义：categorical 字段的词表映射

示例结构：

```json
{
  "osc_1_destination": ["0", "1", "2", "3"],
  "osc_1_wavetable_source_type": ["factory", "custom", "unknown"]
}
```

### 4.8 `route_edge_schema_json`

- 类型：标量字符串
- 含义：路由边 schema 的占位元数据

注意：

- 当前实现里它仍然是 placeholder
- 不应把它当成完整路由定义来源

### 4.9 `corpus_schema_json`

- 类型：标量字符串
- 含义：完整 `CorpusSchema` 的 JSON 序列化

它是 `metadata/param_names` 等字段的“总打包版本”，方便快速导出或复用。

### 4.10 `run_mode`

- 类型：标量字符串
- 取值：`pilot` / `canary` / `full`

### 4.11 `checkpoint_manifest_json`

- 类型：标量字符串
- 含义：HDF5 finalize 时写入的 checkpoint 摘要

当前主要记录：

- 已完成的 `base_preset_id` 列表

## 5. 基本加载示例

### 5.1 用 `h5py` 直接读取

```python
import json
import h5py

h5_path = "experiments/pilot_run/preset_corpus_dataset.h5"

with h5py.File(h5_path, "r") as hf:
    train = hf["train"]
    meta = hf["metadata"]

    param_values = train["param_values"][:]        # (N, D) float32
    present_mask = train["present_mask"][:]        # (N, D) uint8
    embeddings = train["embeddings"][:]            # (N, 1024) float32
    base_ids = train["base_preset_id"][:]
    variant_ids = train["variant_id"][:]
    midi_notes = train["midi_note"][:]

    param_names = [x.decode() if isinstance(x, bytes) else x for x in meta["param_names"][:]]
    param_types = [x.decode() if isinstance(x, bytes) else x for x in meta["param_types"][:]]
    encodings = [x.decode() if isinstance(x, bytes) else x for x in meta["param_value_encoding"][:]]
    category_values = json.loads(
        meta["category_values_json"][()].decode()
        if isinstance(meta["category_values_json"][()], bytes)
        else meta["category_values_json"][()]
    )

print(param_values.shape, embeddings.shape)
print(param_names[:10])
```

### 5.2 解码 categorical 字段

```python
import json
import h5py

def _decode_str(x):
    return x.decode() if isinstance(x, bytes) else x

with h5py.File("experiments/pilot_run/preset_corpus_dataset.h5", "r") as hf:
    train = hf["train"]
    meta = hf["metadata"]

    param_values = train["param_values"][:]
    param_names = [_decode_str(x) for x in meta["param_names"][:]]
    param_types = [_decode_str(x) for x in meta["param_types"][:]]
    encodings = [_decode_str(x) for x in meta["param_value_encoding"][:]]
    category_values = json.loads(_decode_str(meta["category_values_json"][()]))

    name_to_idx = {name: i for i, name in enumerate(param_names)}

    field = "osc_1_destination"
    idx = name_to_idx[field]

    raw_value = param_values[0, idx]
    if encodings[idx] == "category_id":
        vocab = category_values.get(field, [])
        category_id = int(raw_value)
        decoded = vocab[category_id] if 0 <= category_id < len(vocab) else None
    else:
        decoded = raw_value

    print(field, raw_value, decoded)
```

## 6. PyTorch 使用示例

### 6.1 最简单的 `(embedding, params)` 数据集

```python
import h5py
import torch
from torch.utils.data import Dataset


class PresetCorpusDataset(Dataset):
    def __init__(self, h5_path: str, split: str = "train"):
        with h5py.File(h5_path, "r") as hf:
            grp = hf[split]
            self.embeddings = torch.from_numpy(grp["embeddings"][:]).float()
            self.param_values = torch.from_numpy(grp["param_values"][:]).float()
            self.present_mask = torch.from_numpy(grp["present_mask"][:]).float()

    def __len__(self):
        return self.embeddings.shape[0]

    def __getitem__(self, idx: int):
        return {
            "embedding": self.embeddings[idx],
            "param_values": self.param_values[idx],
            "present_mask": self.present_mask[idx],
        }
```

### 6.2 带 metadata 的加载

```python
import json

def load_dataset_with_metadata(h5_path: str, split: str = "train"):

            "base_preset_id": grp["base_preset_id"][:],
            "variant_id": grp["variant_id"][:],
            "route_mask_json": grp["route_mask_json"][:],
            "sample_id": grp["sample_id"][:],
            "midi_note": grp["midi_note"][:],
            "midi_velocity": grp["midi_velocity"][:],
            "midi_duration": grp["midi_duration"][:],
            "rms_db": grp["rms_db"][:],
            "split_local_index": grp["split_local_index"][:],
        }

        metadata = {
            "param_names": [x.decode() if isinstance(x, bytes) else x for x in meta["param_names"][:]],
            "param_types": [x.decode() if isinstance(x, bytes) else x for x in meta["param_types"][:]],
            "param_value_encoding": [x.decode() if isinstance(x, bytes) else x for x in meta["param_value_encoding"][:]],
            "default_values": meta["default_values"][:],
            "corpus_min": meta["corpus_min"][:],
            "corpus_max": meta["corpus_max"][:],
            "presence_ratio": meta["presence_ratio"][:],
            "category_values": json.loads(
                meta["category_values_json"][()].decode()
                if isinstance(meta["category_values_json"][()], bytes)
                else meta["category_values_json"][()]
            ),
            "run_mode": (
                meta["run_mode"][()].decode()
                if isinstance(meta["run_mode"][()], bytes)
                else meta["run_mode"][()]
            ),
        }

    return batch, metadata
```

## 7. 训练和分析时的实用建议

### 7.1 不要直接把所有列都当成连续值

虽然 `param_values` 的存储类型统一是 `float32`，但语义不是统一连续回归：

- `continuous` 是连续数值
- `binary` 是二值数值
- `categorical` 是编码后的类别 ID

训练前应至少根据 `param_types` 做分组分析。

### 7.2 `present_mask` 很重要

如果你忽略 `present_mask`，模型会把“字段缺失但被默认值填充”的样本也当成真实监督，从而引入噪声。更稳妥的做法是：

- 在 loss 中对缺失字段降权或屏蔽
- 至少在分析阶段区分真实值和默认填充值

### 7.3 split 是按 `base_preset_id` 分的

因此：

- 同一 base preset 的所有 variants 都在同一个 split
- 如果你做二次抽样或重划分，不要破坏这个约束

### 7.4 `production_summary.json` 在 HDF5 外部

当前生产摘要并不在 HDF5 metadata 里，而是单独保存在：

- `production_summary.json`

如果你需要全局统计，请记得同时加载这个文件。

## 8. 当前实现边界

### 8.1 `route_edge_schema_json` 还不是正式 schema

当前字段存在，但内容还是 placeholder，只能作为保留位，不应作为训练或分析的正式结构来源。

### 8.2 modulation / wavetable 扩展字段的 sample-level 编码还不完整

当前 schema 已经为这些字段预留列位，但 producer 的 sample-level 编码仍主要读取 `preset.settings`。因此：

- schema 层已经准备好了
- 但某些 modulation / wavetable 扩展字段在当前数据里可能只是默认值占位

### 8.3 embedding 可能存在占位回退

如果运行环境没有正常初始化 MuQ，当前 producer 会写入零向量 embedding。正式训练前请务必检查：

- `embeddings.std()` 是否显著大于 0
- 是否存在大批量全零行

## 9. 推荐排查清单

开始训练前，建议先做以下检查：

1. 确认 `embeddings` 不是零向量占位
2. 确认 `param_names / param_types / param_value_encoding` 三者长度一致
3. 随机抽查几个 categorical 字段能否被正确解码
4. 随机抽查 `present_mask=0` 的列是否真的对应默认值填充
5. 确认同一个 `base_preset_id` 只出现在一个 split 中
6. 确认 `production_summary.json`、`corpus_schema.json` 和 HDF5 来自同一轮运行
